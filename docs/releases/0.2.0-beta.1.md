# ADRProof 0.2.0-beta.1 gate record

Date: 2026-08-31

This record documents why external-provider protocol v1 can enter beta. It
intentionally contains no customer identity, repository path, integration lock,
private source, patch, or private evidence.

## Public verification baseline

Public commit `18d324104acfa4877e8b7446e74df32f5f25d56e` completed GitHub
Actions CI run 14 with all jobs passing:

- the full historical regression suite on Linux;
- response conformance and a native provider process on macOS and Windows;
- formatting and Clippy with warnings denied;
- the pinned RustSec dependency audit.

The beta release commit changed package and documentation metadata only. It
subsequently passed GitHub Actions CI run 15 on all five jobs and was published
as annotated tag `0.2.0-beta.1` pointing to
`6b8efd7eea4b763fa04eaf9f981418be1e44ad19`.

## Sanitized private-pilot result

A private integration workspace pinned ADRProof and the integrating project by
full commit identity. The pilot ran against an isolated checkout and completed
with PASS. It confirmed:

- text and versioned JSON `provider check` output;
- stable logical semantic-input identities after checkout relocation;
- deterministic facts, provenance, and scoped FactCoverage;
- deterministic repeated execution;
- fail-closed behavior for provider identity/version mismatch, undeclared
  inputs, malformed output, and timeout.

No private-project code or name was added to ADRProof, and the pilot found no
release-blocking protocol defect.

## Pilot observations and disposition

The pilot suggested optionally exposing semantic-input content hashes and a
runtime/path-independent semantic digest. These are useful observability ideas,
not protocol-v1 defects. Adding them to the closed provider-check report v1
would change a frozen machine-readable surface, so they are deferred to a
separately versioned report candidate after 0.2.

The v1 report retains operational fields such as `elapsed_ms`; consumers must
not treat them as semantic identity.

## Freeze decision

Beginning with `0.2.0-beta.1`, the following are frozen under the compatibility
rules in [`../VERSIONING.md`](../VERSIONING.md):

- external-provider protocol v1;
- request and response schemas v1;
- provider-check report schema v1;
- exit behavior and diagnostic code families;
- FactCoverage and provenance authority boundaries exercised by the protocol.

Publication, tagging, and release remain maintainer actions. Distribution is
source-only through GitHub; crates.io publication is disabled by the Cargo
manifest.
